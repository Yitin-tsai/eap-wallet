# eap-wallet - LLM Context

> Port 8081 | Context path `/eap-wallet`

## Ownership

- Available and locked currency/energy balances.
- Idempotent order reservation and rejection.
- Explicit-transaction `TradeExecutedEvent` settlement.
- Wallet integration outbox with broker confirms, retry/backoff, `FAILED`, and manual requeue.
- TDA bid reservation, outbox-backed confirmation, and auction-result settlement.

Wallet does not own order state, matching, or MatchEngine completion state.

## Current Flow

```text
OrderSubmittedEvent
  -> insert-first order_id claim
  -> reserve BUY currency or SELL energy
  -> Wallet state + OrderConfirmed/OrderFailed outbox in one transaction

TradeExecutedEvent
  -> one explicit DB transaction
  -> lock buyer/seller Wallet rows in stable UUID order
  -> update assets + validate postconditions
  -> insert trade_settlements(trade_id)
  -> ACK after commit
```

Settlement does not publish `WalletTradeSettledEvent`. The rejected statement-autocommit experiment is not current behavior.

## TDA Flow

```text
AuctionBidSubmittedEvent
  -> reserve maximum auction exposure
  -> Wallet outbox publishes AuctionBidConfirmedEvent

AuctionClearedEvent
  -> settle cleared quantity and release unused reservation
```

The TDA bid listener currently lacks a durable redelivery claim and publishes no rejection result for missing/insufficient Wallet state. Settlement is idempotent per auction/user/side but continues after participant failures. TDA has a distinct contract and no equivalent published CDA correctness/capacity result.

## RabbitMQ Consumers

| Queue | Handler |
| --- | --- |
| `wallet.orderSubmitted.queue` | reserve assets and create confirmation/failure outbox |
| `wallet.tradeExecuted.queue` | idempotent asset settlement |
| `wallet.auctionBidSubmitted.queue` | reserve TDA bid assets and create confirmation outbox |
| `wallet.auctionCleared.queue` | settle TDA auction results |
